## Changes and reasoning

- `tools/s14_package.py` assembles a new exclusive portable ZIP and complete
  tracked-source ZIP. It verifies archive/model/wheel hashes, confines member
  paths, refuses links/collisions/Windows device names, omits development/pip/
  bytecode/debug files and never copies a development virtualenv. Source comes
  only from reviewed tracked paths. Sorted entries, fixed timestamps/modes and
  fixed deflate settings produce byte-identical final builds.
- `packaging/portable.py` and two `.cmd` launchers use the bundled runtime with
  `-I -B`, package-relative model/Tcl paths and a separate private per-user cache.
  No system Python/file association, hidden download or global execution-policy
  change is required. `--self-check` verifies every unpacked file and performs
  both CPU model invocations plus actual Tk creation. The desktop and CLI call
  the existing application service.
- Bundled runtime is **CPython 3.12.16**, python-build-standalone **20261026**,
  Windows x86_64 MSVC, with **Tk 8.6.15**. This intentionally differs from the
  development **3.12.14** interpreter and receives its own actual acceptance.
  The builder used Python 3.12.14 / zlib **1.3.2**. Reproducibility is assembly
  from pinned upstream binaries, not an independent native-binary rebuild.
- `third_party/s14-runtime.json` pins the install-only Python archive and the
  separately verified full archive from which original `PYTHON.json` and
  licensing notices were retained. All 16 existing S04/S05 wheel versions/hashes
  and both unchanged model hashes remain fixed. Wheel metadata/notices and all
  native files are inventoried. Verbatim upstream CRLF/trailing whitespace is
  retained under explicit `.gitattributes` rules without hiding textual diffs.
- Fresh Windows exposed the missing Microsoft C++ dependency. The final launcher
  reports a missing `msvcp140.dll` prerequisite directly. The separately installed
  **Microsoft Visual C++ x64 v14 runtime** is explicit setup; its official tested
  installer **14.51.36247.0** is pinned, Microsoft-signed and not redistributed.
  It installed only inside Sandbox, exit **0**. The host's existing
  **14.44.35211.0** installation was retained. No system DLL was copied into the
  package. The upstream Python distribution's own files/notices remain intact.
- Kdenlive and FFmpeg/ffprobe are also separate local prerequisites. Their
  binaries are not bundled, so this candidate does not assume redistribution
  rights/source obligations for a particular GPL-enabled FFmpeg build. The
  notices link the actual upstream licensing guidance rather than calling every
  FFmpeg build LGPL. Candidate signing is honestly **unsigned**; no paid signing.
- `application.py` fixes a real first-run cache identity defect: Windows MSIX
  redirected a newly created LocalAppData cache between initial/final checks.
  The cache reuse location now binds its stable absolute logical path. Source,
  tool, model, profile and implementation fingerprints still resolve/hash and
  are checked; cache entries retain source/model/settings integrity validation.
  A focused actual-pipeline regression reproduces redirection after creation.
  Actual host first-cache generation now succeeds while its physical path is
  demonstrably redirected. No analysis/planner/export/audio algorithm changed.
