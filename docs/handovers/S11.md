## Changes and reasoning

- [`desktop.py`](../../interview_auto_editor/desktop.py) supplies a Tkinter window,
  starter picker, explicit participant file/ID/name/channel mapping, mapping
  confirmation, Tight/Gentle, four service modes, progress/cancel, private review,
  Keep/Restore and Open copy in Kdenlive. Only existing local assets and reviewed
  records appear in the two small setup dialogs. No timing/inference rule or
  automatic silence/origin approval is implemented in the UI.
- [`desktop_workflow.py`](../../interview_auto_editor/desktop_workflow.py) supplies
  orchestration and strict v1 immutable desktop-job snapshots. Exclusive private
  mapping/optional request/job files sit **beside** the run. Resume explicitly
  picks the original snapshot and applies its original options, with current form
  edits excluded. The unchanged Application service still verifies complete
  input/code/tool/source identities, staging artifacts and caches, owns OS locks
  and publishes only validated new folders atomically. No deletion/repair/rebind
  bypass is added.
- A single non-daemon worker calls Application. Only the owning main thread
  accesses widgets; events carry fixed stages, results or allowlisted actionable
  errors. The form disables during work while Cancel stays usable. Closing a
  busy window requests cooperative cancellation and waits; idle close cancels
  polling callbacks. The combined-suite Tcl teardown finding and fix are recorded
  below. Stage-boundary limitations for pure planning remain unchanged.
- Keep/audible inputs parse exact source seconds, append canonical Overrides and
  call the shared service for validation. They create a pending request for the
  next new run, never mutate the completed run or create gap approvals. Picture
  observations remain original-analysis-bound. Stale S08 refined-result bindings
  **refuse** after pacing/restoration changes; the user must explicitly load
  reviewed rebound approvals or clear cleanup for unity. No silent rebinding.
- Opening Kdenlive verifies historical run hashes, creates a new sibling
  `RUN-edit-<id>/project.kdenlive` at the same directory depth, then launches the
  selected local executable with an argument array/no shell. Relative references
  survive and manual edits do not corrupt the validated run. Process launch is
  not installed-build certification; the actual window was separately observed.
- [`InterviewAutoEditor.pyw`](../../InterviewAutoEditor.pyw) and the desktop module
  are source/packaging entry points. The launcher prefers an already prepared
  repository venv over a different system association and installs nothing.
  Bundled-runtime/clean-install/redistribution acceptance remains S14/S15.
- [Desktop guide](../project/S11_DESKTOP.md), README,
  [compatibility record](../COMPATIBILITY.md),
  [workflow recording](../fixtures/S11_WORKFLOW.md) and
  [aggregate evidence](../fixtures/S11_DESKTOP_EVIDENCE.json) describe observed
  behavior, setup, privacy, recovery and limits. Existing shareable S09/S10 media
  and construction records are reused without new fixture-media publication.

The Application service, CLI, contracts, timing, speech/reaction protection,
planner, turns, cleanup, picture logic, probes/peaks and adapters remain unchanged.
